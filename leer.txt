Resumen General
* Fue creado un archivo llamado "server.js" para ejecutar un servidor local con node.js.
* El sistema frontend fue movido a una nueva carpeta llamada "public".
* Fue creada una carpeta llamada "src" donde se manejar la logica del backend.
* En la carpeta src se crearon archivos para establecer la conexion del sistema con la base de datos y adicionalmente un sistema de conttrol de sesiones con Json Web Tokens con una duracion de 10 minutos, adicional a eso se establecieron roles para identificar al tipo de usuario y se le añadieron restricciones en el sistema.
* Se añadieron archivos a la carpeta js para gestionar los tokens y conectar el login con el backend.
* La mayoria de archivos html fueron vinculados al decodificador de jwt y al modulo de seguimiento de sesion.

****Notas importantes****
- Para que el sistema funcione se debe configurar el modulo db.js ubicado en src/config con los datos de la conexion con la base de datos.
- Para que el sistema funcione correctame la versión de "MariaDB" que se debe de utilizar es la "11.9.2 Rolling" o superior de lo contrario el sistema dara error

Funcion de nuevos archivos:
* login.js: 
	- Envia el correo y contraseña al backend. 
	- Recibe un token JWT, el rol del usuario y las rutas permitidas guardandolas en el `localStorage` del navegador.

* authValidation.js: 
	- Verifica si hay un token, un rol y rutas permitidas en `localStorage`.
	- Compara la ruta actual con las rutas permitidas para el rol del usuario.
	- Redirige al usuario al login si no tiene permiso o si el token ha expirado.

* tokenManager.js:
	- Verifica el tiempo restante antes de que el token expire.
	- Muestra una alerta 2 minutos antes de la expiración.
	- Redirige automáticamente al login cuando el token expira.
	- Elimina el token, el rol y las rutas permitidas de `localStorage` al expirar.

* db.js:
	- Configuracion de la conexion de la base de datos.


* authController.js:
	- Recibe el coreo y contraseña del archivo login.js y los valida en la base de datos.
	- Genera un token JWT si los datos son correctas.
	- Devuelve el token y el rol del usuario al frontend.
	- Maneja la renovación del token cuando está a punto de expirar.

* checkJWT.js:
	- Extrae el token del encabezado de la solicitud.
	- Verifica si el token es válido y no ha expirado.
	- Añade la información del usuario decodificada para su uso en otras rutas.


* authRoutes.js:
	- Define la ruta `/login` para el inicio de sesión.
	- Define la ruta `/allowed-routes` para obtener las rutas permitidas según el rol del usuario.
	- Define la ruta `/refresh-token` para renovar el token JWT.

* generateJWT.js:
- Recibe los datos del usuario (ID y rol).
- Firma el token con una clave secreta.
- Establece un tiempo de expiración de 10 minutos para el token.
